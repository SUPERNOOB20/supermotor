Frequently Answered Questions :p





Q: What is supermotor?
A: My 2D, C++ game engine




Q: Then what is a game engine?
A: Game engines are tools that help you make games!! In my opinion, they are best suited for when you want to make a lot of similar games, because the idea is to re-use features that they might have in common (think of physics, memory management, viewports, cameras, and interfaces, for instance)

Anyway, game engines are waaay too overrated. I always make the silly joke that you can make a game_engine.h with just one line of code:

typedef unsigned long long int score

But it's true! I would absolutely already consider that to be a game engine :3




Q: No 3D?
A: That's right, no 3D. There are some 3D-compatible functions, but supermotor will never ever fully support 3D.
Though it would be really cool to someday make yet another game engine that is fully focused on 3D! That's what I'm studying for, at least :)




Q: Who is it meant for?
A: Me! I use it to make my videogames, animations, interfaces, video editors and various other tools, utilities, and software.
Open-source is cool, though! So I tried to make supermotor as easy for others to learn as possible. You can always [](contact) me if there's anything you need help with about understanding my tool or the docs ^_^ (or if you have any suggestions :3)




Q: Why make a game engine at all? Why reinvent the wheel?
A: "Making a game engine is like re-inventing the wheel once. But not making a game engine will force you to re-invent the wheel every single time" ~ SUPERNOOB20




Q: No, but seriously, why? Can't you just use Unity/Godot/UE/raylib(some other game engine here)?
A: Computer Science and Math aren't dead things in a book. Science always keeps evolving! Engineering can always be reinvented. We keep improving our science and inventions precisely because we keep on trying to improve over already-existing things. (This is where optimization comes from, for example. Along with more "soft-qualities" like accessibility, ease of use, maintenability, robustness, etc. etc. boring boring I only care about optimization because I love it :3)

Think about cooking - making new dishes can be just as fun as preparing already-existing ones!

Also, making things yourself is the best for learning purposes. supermotor is meant to sport a tiny codebase you can quickly learn and harness to add more code to it or make your own game engine with what you learnt.




Q: Fine, I'm bought, I want to get started! Do I need to learn how to code?
A: Basic knowledge about C/C++, yes. If you can use variables, datatypes, basic data structures, and basic functions and classes, you should be good to give it a go (and you can always ask me or others for help if needed!!! There never is such thing such as a "stupid question" ^_^)

Extra knowledge about object-like macros, templates, namespaces, malloc, pointers, etc. isn't strictly required to use supermotor, but might help you understand the source code better.




Q: Is supermotor high-level or low-level?
A: Supermotor is [section_dependencies](a high-level library built on top of a few low-level libraries). This is intentional, as it means that you will have an easy time learning and using supermotor, while still harnessing _some_ of that low-level efficiency.




Q: I don't like high-level.
A: Understandable. That's absolutely fine. I will be looking forward to your RISC ASM game engines, then :3
